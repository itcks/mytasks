# MyTasks — веб-система учёта задач и заявок

Готовое веб-приложение для небольших команд: сотрудники создают задачи,
инженеры их выполняют, администратор контролирует весь процесс.

Node.js (Express) + SQLite на сервере, ванильный JavaScript на клиенте.
Один процесс обслуживает и статику, и API — деплой максимально простой.

## Возможности

**Задачи**
- Полный жизненный цикл: Новая → В работе → Выполнена / Отклонена
- Дата и время задачи, срок исполнения (автоматически — до конца дня, если не задан)
- Приоритеты (низкий / средний / высокий), теги для группировки
- Повторяющиеся задачи: ежедневно, еженедельно, ежемесячно — копия создаётся сама
- Комментарий при выполнении, просрочка подсвечивается в списке и календаре
- Вложения (фото, файлы, до 10 МБ) с комментариями к задаче

**Работа команды**
- Три роли: пользователь создаёт, инженер выполняет, администратор управляет всем
- Назначение и переназначение исполнителей (в админке и на доске)
- Уведомления о назначении задач, смене статуса, напоминания о сроке (за 24 ч) и просрочках
- Готовый канал доставки уведомлений в мессенджер МАКС (Bot API)
- Kanban-доска: перетаскивание карточек мышью и пальцем на мобильных
- Календарь с дедлайнами: названия задач кликабельны и ведут к карточке
- Поиск, фильтры по статусу/приоритету/тегу, пагинация, выбор количества записей
- История изменений каждой задачи (кто, когда и что менял) — полный аудит

**Администрирование**
- Админ-панель: все задачи всех пользователей, управление ролями и пользователями
- Отчёты: объём, выполнение, просрочки, нагрузка и среднее время по исполнителям, период
- Выгрузка задач в CSV (открывается в Excel)

**Интерфейс**
- Светлая и тёмная темы, переключатель на странице, автопереключение по времени суток
- Адаптив для мобильных устройств

## Быстрый старт (локально)

Требуется Node.js 18+ (LTS).

```bash
git clone https://github.com/itcks/mytasks.git
cd mytasks/server
npm install
node server.js
```

Откройте http://localhost:3000

Учётные записи по умолчанию (создаются при первом запуске — смените пароли):

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin123 | Администратор |
| engineer | engineer123 | Инженер |

Новые пользователи регистрируются на странице `/register.html` или прямо в админке.

## Установка на сервер (одна команда)

Готовый скрипт ставит всё: Node.js, nginx, HTTPS Let's Encrypt, systemd-сервис.

Подойдёт любой Debian 12 / Ubuntu (в том числе LXC-контейнер на Proxmox).

```bash
curl -fsSL https://raw.githubusercontent.com/itcks/mytasks/main/deploy/install.sh -o install.sh
sudo bash install.sh tasks.example.ru токен-бота-МАКС
```

`tasks.example.ru` — ваш домен, A-запись которого указывает на сервер,
порты 80 и 443 открыты. Сертификат, HTTPS, автопродление и автозапуск
настроятся автоматически. Токен бота МАКС можно указать вторым аргументом
или ввести при запросе скриптом (пропуск — уведомления останутся только
в веб-интерфейсе). Скрипт проверяет токен через Bot API и включает доставку
уведомлений в МАКС.

Без домена (внутренняя сеть):

```bash
sudo bash install.sh
# приложение будет на http://IP:3000, HTTPS можно добавить позже той же командой
```

Подробные инструкции по созданию контейнера Proxmox: [deploy/proxmox-ct.md](deploy/proxmox-ct.md)

## Конфигурация

Файл `server/.env` (создаётся скриптом, шаблон — `server/.env.example`):

| Переменная | Назначение |
|---|---|
| `JWT_SECRET` | Секрет JWT-токенов (обязательно, генерируется скриптом) |
| `BOT_API_KEY` | Ключ прямого API бота (заголовок `X-Bot-Key`) |
| `NODE_ENV` | `production` — сервер слушает только 127.0.0.1 (за reverse-proxy) |
| `MAX_BOT_TOKEN` | Токен бота МАКС — включает доставку уведомлений в мессенджер |

База данных — файл `server/data.sqlite`, создаётся и мигрируется автоматически.
Делайте его копию перед обновлениями.

## Интеграция с МАКС (бот)

Приложение рассылает уведомления через Bot API МАКС. Подключение:

1. Создайте бота через @MasterBot в МАКС, получите токен.
2. В `server/.env` впишите `MAX_BOT_TOKEN=...` и перезапустите сервис.
3. Публичный HTTPS-адрес уже обеспечен настройками из скрипта установки.

## Обновление без потери данных

База данных (`server/data.sqlite`) и конфигурация (`server/.env`) находятся
вне git и не перезаписываются при обновлении. Скрипт обновления перед каждым
запуском сам делает их резервную копию в `/var/backups/mytasks`
(хранятся последние 30):

```bash
sudo bash /opt/mytasks/deploy/update.sh
```

Скрипт: останавливает сервис → бэкапит базу и `.env` → `git pull` →
`npm install` → запускает сервис → проверяет ответ сервера. Если что-то
пошло не так, печатает команды отката на предыдущий коммит и восстановления
базы из бэкапа.

Миграции схемы БД выполняются автоматически при старте сервера: добавляются
только новые колонки и таблицы, существующие данные сохраняются.

## Обслуживание

```bash
# Обновление приложения
cd /opt/mytasks && git pull && systemctl restart mytasks

# Логи
journalctl -u mytasks -f

# Статус
systemctl status mytasks
```

## Стек

- Сервер: Node.js, Express, SQLite (встроенный `node:sqlite`), JWT, bcrypt
- Клиент: ванильный JavaScript, без сборки и зависимостей
- Прокси: nginx или Apache (конфиги в `deploy/`)
- Уведомления: внутренние + MAX Bot API

## Структура репозитория

```
server/        — API, БД, уведомления, установка (.env.example, init-миграции)
client/        — страницы: список задач, доска, админка, вход/регистрация, темы
deploy/        — install.sh, конфиги nginx/Apache, systemd, гайды (Proxmox, Synology)
```
